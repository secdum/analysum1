# SARIF 2.1.0 Specification - secdojo-scan

This document defines how static analysis results for C and Rust must be structured to ensure compatibility with the **SARIF (Static Analysis Results Interchange Format) v2.1.0** format.

## 1. File Structure
Each report generated by the `secdojo-scan` tool must be a valid JSON object following the official schema.

### Mandatory Fields in the Root Object
* `$schema`: Must be `https://json.schemastore.org/sarif-2.1.0.json`.
* `version`: Must be `"2.1.0"`.
* `runs`: A list containing the tool execution.

## 2. Tool Mapping (Drivers)
The `tool.driver.name` field must be populated with the name of the module that generated the alert.

| Language | Integrated Tools |
| :--- | :--- |
| **C** | `Cppcheck`, `Flawfinder`, `Semgrep` |
| **Rust** | `cargo-audit`, `cargo-geiger`, `Clippy` |

## 3. Severity Levels
All parsers must map the original tool severity to the SARIF `level` field:

| Original Severity | SARIF `level` | Description |
| :--- | :--- | :--- |
| Critical / High | `error` | Severe flaws, buffer overflows, active CVEs. |
| Medium | `warning` | Potential vulnerabilities or use of insecure functions. |
| Low / Info | `note` | Style warnings or code improvements (e.g., Clippy). |
